# 04. アセンブラ — C の下で CPU がしていることを読む

アセンブラは CPU 命令を人が読めるニーモニックで書く言語です。C を置き換えてすべてを書くためというより、起動コード、割り込み、性能・サイズ・不具合の調査で「コンパイラが何を出したか」を読めるようにするのが目的です。

命令名・レジスタ名・呼出規約はアーキテクチャごとに異なります。このノートの例は ARM Thumb 系でよく見かける形ですが、使用する MCU のアセンブラマニュアルと ABI を正としてください。

## 1. CPU が扱うもの

| 要素 | 役割 | C との対応 |
| --- | --- | --- |
| レジスタ | CPU 内部の高速な作業領域 | 局所変数、引数、戻り値の一部 |
| プログラムカウンタ（PC） | 次に実行する命令の位置 | 実行位置 |
| スタックポインタ（SP） | スタックの先頭 | ローカル変数、保存したレジスタ |
| リンクレジスタ（LR） | 関数から戻る位置（ARM 系） | return address |
| フラグ | 演算結果の状態 | `if` / 比較の条件 |
| メモリ | Flash、SRAM、周辺レジスタ | 配列、構造体、グローバル変数 |

代表的なフラグには `Z`（結果が 0）、`N`（負）、`C`（桁上がり／借り）、`V`（符号付き演算のオーバーフロー）があります。条件分岐は比較結果そのものではなく、これらのフラグを見ることが多いです。

## 2. 命令の基本形

```text
label:  mnemonic  operands    ; コメント
loop:   adds      r1, r1, r0  ; r1 = r1 + r0
```

| 種類 | 例 | 意味 |
| --- | --- | --- |
| データ転送 | `ldr`, `str`, `mov` | メモリ・レジスタ・即値を移す |
| 算術・論理 | `add`, `sub`, `and`, `orr`, `eor` | 演算やビット操作をする |
| 比較・分岐 | `cmp`, `bne`, `beq`, `b` | フラグに応じて次の命令を変える |
| 関数呼出し | `bl`, `bx`, `push`, `pop` | 呼出し、復帰、保存を行う |
| システム | `cpsid`, `wfi` など | 割り込み制御、低消費電力待機など |

`ldr` / `str` は load / store です。多くの RISC 系 MCU では、算術命令はレジスタ同士で行い、メモリの値はまず `ldr` でレジスタに読み込みます。

## 3. C のループを追う

次の C を考えます。

```c
unsigned sum_to(unsigned n) {
    unsigned sum = 0;
    while (n != 0) {
        sum += n;
        --n;
    }
    return sum;
}
```

概念的には次のような命令列になります（最適化、CPU、ABI により実際の出力は変わります）。

```asm
    movs r1, #0          ; sum = 0
loop:
    cmp  r0, #0          ; n == 0 ?
    beq  done            ; ならループを抜ける
    adds r1, r1, r0      ; sum += n
    subs r0, r0, #1      ; --n
    b    loop
done:
    mov  r0, r1          ; 戻り値を r0 に置く（ARM ABI の例）
    bx   lr              ; 呼出し元へ戻る
```

`r0` が引数 `n` と戻り値、`r1` が `sum` に使われるのは、よくある ARM ABI の取り決めです。C の変数名は最終的な機械語には残らないことが多く、最適化を有効にするとループ自体が別の形になったり、式に置換されたりします。

## 4. アドレッシングとポインタ

```c
value = buffer[index];
```

これは概念的に「`buffer` の先頭アドレス + `index × 要素サイズ` を計算し、そのアドレスからロードする」処理です。配列境界を越えると、C では未定義動作になり、MCU では別の変数や周辺レジスタを壊す原因にもなります。

周辺レジスタもアドレスにある値です。たとえば `volatile uint32_t *reg` への代入は、概念上はレジスタに値を置き、`str` でそのアドレスに書く処理になります。逆アセンブルを読むと、意図した幅（8/16/32 bit）でアクセスしているかも確認できます。

## 5. 関数呼出しとスタック

```text
呼出し元                    呼出し先
引数を規約どおり配置 ──bl──> 必要なレジスタを保存
戻り値を受け取る <──bx lr──  処理して戻り値を配置
```

関数をまたいで保持すべきレジスタや、呼出し側が破壊を許容するレジスタは ABI で決まります。割り込みが入ると CPU は復帰に必要な状態を保存しますが、ISR 側でもコンパイラや CPU の定める保存規則に従う必要があります。通常は SDK が用意する ISR 宣言とスタートアップコードを使い、独自のアセンブラ ISR は根拠を持って最小限にします。

## 6. 実務での読み方

1. まず C のソース、コンパイラオプション、対象 CPU を確認する。
2. 逆アセンブルで関数の入口、分岐、メモリアクセス、関数呼出しを探す。
3. 期待しない最適化、符号拡張、割り込み禁止区間、`volatile` アクセスを C と照合する。
4. 命令サイクル、Flash wait state、キャッシュ、分岐予測の有無は、必要になってから対象 MCU の資料で確認する。

アセンブラで「速そう」に見えるコードが速いとは限りません。周辺バス待ち、Flash からのフェッチ、割り込み、I/O 待機が支配的なこともあります。測定してから最適化します。

## セルフチェック

1. `cmp` が通常直接変更するのは、汎用レジスタかフラグか。
2. `beq` はどのような条件で分岐するか。
3. `ldr` と `str` の役割をそれぞれ説明できるか。
4. C の `volatile` ポインタへの書込みがアセンブラ上で重要になる理由は何か。

<details>
<summary>答え</summary>

1. フラグ。比較結果により `Z` などが更新される。  
2. 比較などで Z フラグがセットされている（equal）とき。  
3. `ldr` はメモリからレジスタへ読み込む、`str` はレジスタからメモリへ書き込む。  
4. 周辺レジスタへの書込みは物理デバイスを動かすため、コンパイラに省略・勝手な統合をさせず、意図したアクセス幅・順序を確認する必要がある。
</details>
