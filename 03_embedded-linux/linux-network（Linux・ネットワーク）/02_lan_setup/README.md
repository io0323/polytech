# 02. LAN 構築 — 小さなネットワークを設計して確かめる

実習や現場では、PC・Raspberry Pi・センサ機器を同じ LAN につなぎ、相互に通信できる状態を自分で作ります。機器の役割と、アドレスを決める手順を押さえます。

## 1. LAN を構成する機器

| 機器 | 主に扱う層 | 役割 |
| --- | --- | --- |
| LAN ケーブル | L1 | 信号を伝える。カテゴリ（Cat5e、Cat6 など）で対応速度が変わる |
| リピータハブ | L1 | 受けた信号を全ポートに流す（現在はほぼ使わない） |
| スイッチ（L2 スイッチ） | L2 | MAC アドレステーブルを学習し、宛先のポートにだけフレームを転送する |
| ルータ | L3 | 異なるネットワーク間で IP パケットを転送する。家庭用は NAT・DHCP・Wi-Fi を兼ねることが多い |
| 無線 LAN アクセスポイント | L2 | Wi-Fi 端末を有線 LAN につなぐ |
| L3 スイッチ | L2/L3 | スイッチにルーティング機能を持たせたもの。VLAN 間の通信に使う |

```text
            インターネット
                  │
           ┌──────┴──────┐
           │   ルータ     │  192.168.1.1（デフォルトゲートウェイ / DHCP / DNS 中継）
           └──────┬──────┘
                  │
           ┌──────┴──────┐
           │  L2 スイッチ │
           └─┬────┬────┬─┘
             │    │    │
           PC   RasPi  AP ─ ─ ─ 無線端末
```

## 2. LAN ケーブル

- **ストレートケーブル**: PC とスイッチなど、異なる種類の機器をつなぐ。現在の標準。
- **クロスケーブル**: 同じ種類の機器同士をつなぐ。最近の機器は **Auto MDI/MDI-X** で自動判別するため、ストレートで足りることがほとんど。
- コネクタは RJ-45。配線規格は T568A / T568B があり、両端を同じ規格にするとストレートになる。

## 3. アドレス設計の手順

1. **ネットワークアドレスを決める**: 例 `192.168.1.0/24`。既存のネットワークと重ならないようにする。
2. **固定アドレスと DHCP の範囲を分ける**

| 範囲 | 用途 |
| --- | --- |
| `192.168.1.1` | ルータ（デフォルトゲートウェイ） |
| `192.168.1.2` 〜 `.49` | サーバ、プリンタ、Raspberry Pi など固定で使う機器 |
| `192.168.1.100` 〜 `.199` | DHCP で PC やスマートフォンに配る |

3. **ゲートウェイと DNS サーバを決める**: 端末には「自分の IP / サブネットマスク / デフォルトゲートウェイ / DNS サーバ」の 4 点を設定する。
4. **一覧表に残す**: どの機器にどのアドレスを付けたかを記録しないと、重複や行方不明が起きる。

## 4. DHCP と DNS

**DHCP** は端末に IP アドレスなどを自動で配る仕組みです。やり取りは 4 段階です。

```text
端末 ── DISCOVER（DHCP サーバいますか）──→ ブロードキャスト
端末 ←─ OFFER（このアドレスはどうですか）── サーバ
端末 ── REQUEST（それを使います）────────→
端末 ←─ ACK（了解。リース期間は〜）────── サーバ
```

IoT 機器にサーバ的な役割（MQTT ブローカーなど）を持たせるときは、**固定 IP** にするか、ルータ側で MAC アドレスに対して同じアドレスを配る **DHCP 予約** を使います。

**DNS** はホスト名を IP アドレスに変換する仕組みです。LAN 内では `raspberrypi.local` のように **mDNS**（Avahi / Bonjour）で名前解決できることもあります。

## 5. Linux での設定と確認

Raspberry Pi OS（Bookworm 以降）や多くのデスクトップ向けディストリビューションでは **NetworkManager** がネットワークを管理し、`nmcli` で操作します。

```sh
# 接続の一覧
nmcli connection show

# 有線接続に固定 IP を設定する（接続名は環境により異なる）
sudo nmcli connection modify "Wired connection 1" \
  ipv4.method manual \
  ipv4.addresses 192.168.1.20/24 \
  ipv4.gateway 192.168.1.1 \
  ipv4.dns 192.168.1.1
sudo nmcli connection up "Wired connection 1"

# Wi-Fi に接続する
sudo nmcli device wifi connect "SSID名" password "パスワード"
```

Ubuntu Server では `/etc/netplan/*.yaml` を編集して `sudo netplan apply` で反映する方式が一般的です。

確認は次の順で行います。

```sh
ip link              # リンク（ケーブル・無線）が UP か
ip addr              # IP アドレスが付いているか
ip route             # default via 192.168.1.1 があるか
ping -c 3 192.168.1.1     # ゲートウェイに届くか
ping -c 3 8.8.8.8         # インターネットに IP で届くか
ping -c 3 example.com     # 名前解決できるか
```

## 6. VLAN とセキュリティ

- **VLAN** は 1 台のスイッチを論理的に複数の LAN に分ける機能です。IoT 機器を事務用 PC と別の VLAN に分けると、乗っ取られた機器からの被害を抑えられます。
- 初期パスワードのまま機器を LAN につながない。ルータ・Raspberry Pi・カメラは最初に変更する。
- 不要なポートは閉じ、外部（インターネット）から LAN 内機器へ直接ポートを開けない。遠隔保守には VPN を使う。
- Wi-Fi の暗号化は WPA2 以上（可能なら WPA3）を使う。

## セルフチェック

1. MAC アドレスを学習して宛先ポートにだけ転送する機器は何か。
2. 端末が通信するために必要な 4 つの設定項目は何か。
3. DHCP の 4 つのメッセージを順に挙げよ。
4. サーバ役の Raspberry Pi のアドレスを変わらないようにする方法を 2 つ挙げよ。
5. `ping 8.8.8.8` は通るが `ping example.com` が通らないとき、まず疑う設定は何か。

<details>
<summary>答え</summary>

1. L2 スイッチ。  
2. IP アドレス、サブネットマスク、デフォルトゲートウェイ、DNS サーバ。  
3. DISCOVER → OFFER → REQUEST → ACK。  
4. 機器側で固定 IP を設定する／ルータで DHCP 予約をする。  
5. DNS サーバの設定（名前解決）。
</details>
